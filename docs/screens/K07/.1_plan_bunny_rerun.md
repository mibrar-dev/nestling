### 0.3 §0 — the deliberate KID BACKGROUND deviation (unchanged, restated)

The brief's KID BACKGROUND rule says every K screen gets `KidScope` (sky
gradient + meadow hills). **K07 must NOT use `KidScope`:**

- `K07-evolution.html:16` overrides the kid background:
  `.screen.kid { background-color: var(--surface); background-image:
  var(--kid-stars), radial-gradient(118% 62% at 50% 36%, var(--lilac-tint) 0%,
  var(--surface) 58%, var(--lilac-tint) 100%); }` — a lilac radial glow on
  surface, NOT the sky/meadow gradient.
- The K07 body contains **no `.meadow` element** (the `.meadow` rules at lines
  7–9 are dead boilerplate), so "use the shared one exactly as the HTML places
  it" has nothing to place.
- Both design PNGs show no sky gradient and no hills (light = white + lavender
  glow; dark = dark purple + pinprick stars).

So the view paints a screen-local background (own feature,
`presentation/widgets/` — RULES §1-legal): surface base + the exact-CSS radial
glow (`PipEvolutionGlow`) + the **shared** `NestKidStarsPainter` in dark only
(`PipEvolutionStars`). No local hills anywhere. The BOTTOM EDGE owner rule
still holds (§(a).9). The orchestrator is asked to record this deviation in
`SHARED_REQUEST.md`; if it instead rules that hills win, swap `PipEvolutionGlow`
for `KidScope` and re-run the UI stage (artwork and copy change with it).

**[F3] The narrow-width fix (K07-BUG-2), exactly:**

```dart
// `EvolutionStageGeometry` gains one derived constant — no literal:
//   /// `.k7-stage { width: 100% }` at the design's 390 px: 390 − 20 − 20.
/// static const double contentWidth = NestDevice.width - NestSpacing.padSide * 2;   // 350

SizedBox(                                   // the slot's OUTER box: 250 tall at
  height: EvolutionStageGeometry.slotHeight, // every width, full width — the rows
  width: double.infinity,                   // below it never reflow
  child: LayoutBuilder(
    builder: (context, constraints) {
      final Widget stage = Stack(
        clipBehavior: Clip.none,
        children: <Widget>[ /* the three slots in the table above */ ],
      );
      if (constraints.maxWidth >= EvolutionStageGeometry.contentWidth) return stage;
      // Below 350 px the three CSS slots cannot fit (2 + 68 + 6 + 30 + 6 + 240 = 352),
      // so the WHOLE composition scales down as one unit, bottom-anchored.
      return FittedBox(
        fit: BoxFit.scaleDown,
        alignment: Alignment.bottomCenter,
        child: SizedBox(
          width: EvolutionStageGeometry.contentWidth,   // 350
          height: EvolutionStageGeometry.slotHeight,    // 250
          child: stage,
        ),
      );
    },
  ),
)
```

Rules for this edit:

- The `LayoutBuilder` sits **inside** the slot's outer `SizedBox(height: 250,
  width: double.infinity)`; replacing that wrapper with a bare `LayoutBuilder`
  would let the slot collapse to the painted height below 350 px and shift every
  row under it.
- At `maxWidth >= 350` (390 and 430) the plain `Stack` is returned, so the CSS
  geometry is **byte-identical** to iteration 1 — every pin in
  `pip_evolution_widget_test.dart` (old pip at `slot.left + 2`, arrow left 76 /
  bottom 24, new pip at `slot.right − 6 − 240`) still holds, and CSS's own
  behaviour at 430 (left/right anchored) is preserved.
- At 320 px (content 280) the scale is `280 / 350 = 0.8` and the painted 280 px
  child exactly fills the slot, so every CSS offset scales by 0.8: old Pip
  x 21.6..76 (bottom 3.2 above the slot's bottom line), arrow x 80.8..104.8
  (bottom 19.2 above it), new Pip x 103.2..295.2 (240 → 192, bottom-anchored) —
  the design's own 2 px arrow tuck scales to 1.6 px, inside the `≥ −2` budget of
  the `K07-BUG-2` proof.
- Never wrap the slot in `MediaQuery`-width branches; never shrink only the
  grown Pip (that is what caused the overlap).
- `FittedBox` transforms hit-testing, so nothing becomes untappable.

### (b).2 `PipState` — per-stream arrival + failure **[F2]**

The root cause of `K07-BUG-1`: `PipStatus.loaded` is published by **either**
stream, so no view can tell "my stream has not emitted yet" from "my stream
failed". Give each stream its own lifecycle and derive each screen's verdict
from **its own** stream only.

```dart
/// One of the feature's two load streams (K06's nest, K07's evolution).
enum PipStreamStatus {
  /// No emission and no error yet — the screen must still say "loading".
  pending,
  /// It emitted: a value, or null for "no active child".
  ready,
  /// It errored. Its subscription was released, so a retry re-subscribes.
  failed,
}

/// What a screen can honestly show, derived from ONE stream.
enum PipPhase { loading, ready, failed, noChild }
```

`PipState` gains exactly two fields (plus the two getters):

```dart
  final PipStreamStatus nestStatus;        // default PipStreamStatus.pending
  final PipStreamStatus evolutionStatus;   // default PipStreamStatus.pending

  /// K06's verdict — from the NEST stream alone.
  PipPhase get nestPhase => nest != null
      ? PipPhase.ready
      : switch (nestStatus) {
          PipStreamStatus.pending => PipPhase.loading,
          PipStreamStatus.ready => PipPhase.noChild,
          PipStreamStatus.failed => PipPhase.failed,
        };

  /// K07's verdict — from the EVOLUTION stream alone.
  PipPhase get evolutionPhase => evolution != null
      ? PipPhase.ready
      : switch (evolutionStatus) {
          PipStreamStatus.pending => PipPhase.loading,
          PipStreamStatus.ready => PipPhase.noChild,
          PipStreamStatus.failed => PipPhase.failed,
        };
```

Copy-with helpers (every one carries both new fields through `props`):

| helper | change |
|---|---|
| `toLoading()` | also resets both stream statuses to `pending` (a retry shows the spinner again). Data is carried as today, and because `…Phase` checks the data first, a reload over existing data keeps the screen instead of flashing the spinner. |
| `copyWithLoaded(next)` | `status: loaded`, **`nestStatus: ready`**, clears `errorMessage`, carries `evolution` + `evolutionStatus` untouched |
| `copyWithEvolution(next)` | `status: loaded`, **`evolutionStatus: ready`**, clears `errorMessage`, carries `nest` + `nestStatus` untouched |
| `withNestStreamError(error)` | new: keeps data + `status`, `nestStatus: failed`, records `errorMessage` (mid-session error keeps the loaded screen, K03 review-finding-6) |
| `withEvolutionStreamError(error)` | same, for `evolutionStatus` |
| `toNestFailure(error)` / `toEvolutionFailure(error)` | replace `toFailure(error)`: `status: failure`, drops the data, records `errorMessage`, and marks **that** stream `failed` (without this the phase would read `loading` and the card would never paint) |
| `withActionStarted` / `withActionFailed` | carry the two new fields (unchanged otherwise) |

`errorMessage` stays the diagnostic record only — **no view may render it**
(raw DB text must never reach a kid screen; `pip_evolution_bloc_test.dart`
already pins that). `props` grows 6 → 8; update the
`expect(const PipState().props, hasLength(6))` pin with a comment.

### (b).3 `PipBloc` — routing each event to its own stream **[F2]**

`PipLoadRequested` keeps opening both streams under the same live-subscription
guards (`:49`), and `close()` still cancels both. Only the four handlers change:

```dart
  void _onNestReceived(PipNestReceived e, Emitter<PipState> emit) =>
      emit(state.copyWithLoaded(e.nest));                     // unchanged call
  void _onEvolutionReceived(PipEvolutionReceived e, Emitter<PipState> emit) =>
      emit(state.copyWithEvolution(e.evolution));             // unchanged call

  void _onNestFailed(PipNestFailed e, Emitter<PipState> emit) {
    if (state.nest != null || state.evolution != null) {
      emit(state.withNestStreamError(e.error));               // mid-session: keep the screen
    } else {
      emit(state.toNestFailure(e.error));
    }
  }
  void _onEvolutionFailed(PipEvolutionFailed e, Emitter<PipState> emit) {
    if (state.nest != null || state.evolution != null) {
      emit(state.withEvolutionStreamError(e.error));
    } else {
      emit(state.toEvolutionFailure(e.error));
    }
  }
```

**No view may branch on `PipStatus` any more** — that cross-stream switch is
the bug. `status` remains for the feature's summary and its existing tests; the
views switch on the phases instead:

```dart
// views/pip_evolution_view.dart (K07)

  case PipPhase.failed:   return _EvolutionFailure(profile: state.nest?.profile);

// views/pip_nest_view.dart (K06 — the same defect, fixed once)

  case PipPhase.ready:    return _PipNestBody(nest: state.nest!);

```
