TASK — Nestling launch splash: Pip hatching (shared/splash)

Goal: when the app cold-starts, the user sees the native splash, then a short animated in-app splash of Pip hatching from the egg, then the app's normal first route. Owner rules: total animated part ≤ 1.6 s, skippable by a tap anywhere, honours Reduce Motion, never delays a returning user more than needed.

1. Native splash (`flutter_native_splash`, latest stable, dev_dependency + config): background = the app icon background colour (leaf green, take the exact hex from design/flutter-asset-pack/assets/brand/app_icon_background.svg), centred image = the egg (Pip stage 1 / `PipEgg` look). Produce a 1024² transparent PNG of the egg for the native splash under app/assets/brand/splash_egg.png — render it from the existing art in app/assets (PipAvatar mochi sunny stage 1 / the Rive `PipEgg` artboard still) with a small committed script or a Flutter golden-to-PNG test helper; same art, no redraw. iOS (incl. dark: use the same green) + Android 12 splash API (icon on green, no branding image). Generate with `dart run flutter_native_splash:create`; commit generated files.
2. In-app animated splash: new widget in app/lib/app/launch_splash.dart (app shell, not a feature): green background identical to the native splash so the hand-off is seamless (egg at the same size and centre as the native image → no jump). Play the hatch with the existing Rive Pip (`PipAvatar`/`PipRive`, mochi sunny): start at stage 1 egg, fire the existing `evolve` trigger to stage 2 hatchling; hold briefly; then cross-fade (≤ 200 ms) into the router. Total from first in-app frame to router ≤ 1600 ms (use a hard timeout so it can never hang if Rive fails to bind). Tap anywhere skips immediately. `MediaQuery.disableAnimations` (Reduce Motion) or `LaunchFlags.disableAnimations` → no hatch: show the hatchling still for ≤ 300 ms (or go straight on), no motion. Semantics: a single label "Nestling" on the splash; it must not trap focus.
3. Wiring: show the splash only on a real cold start of the app (main.dart / app widget), BEFORE the router's first screen; the router's redirect logic and `INITIAL_ROUTE`/`SEED` flags must keep working. Add `LaunchFlags.skipSplash` (`SKIP_SPLASH=1`) and make it default ON whenever `INITIAL_ROUTE` is set, so tools/screens/shot.sh screenshots and all existing widget tests are unaffected. No feature code changes.
4. Tests: widget tests with fake async — splash ends ≤ 1.6 s; tap skips; Reduce Motion path shows no animation; hard timeout fires if the Rive controller never binds; INITIAL_ROUTE skips the splash. `cd app && flutter analyze` (No issues found) and `flutter test --timeout 120s` in the FOREGROUND (all green).

Extract 5 frames into docs/brand/splash_frames.png (ffmpeg if installed, else skip and say so).
